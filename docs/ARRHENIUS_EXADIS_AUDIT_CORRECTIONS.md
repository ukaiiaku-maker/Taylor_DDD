# Audit corrections for the Arrhenius ExaDiS scaffold

This document records the correction of overclaims and physics errors in the first `arrhenius-exadis-strain-hardening` scaffold.

## Corrected status

The branch is a scaffold. It is not yet an Arrhenius-enabled ExaDiS implementation.

What exists:

- Shared Python transition-state utilities for EXP-floor barriers and Arrhenius hazards.
- A stock ExaDiS launcher/adapter that can run the public FCC Cu strain-hardening module stack when `pyexadis` is available.
- A self-contained C++ header that fixes the intended native hook interfaces for later migration into ExaDiS source.
- Documentation of the mechanism mapping and validation hierarchy.

What does not exist yet:

- No native ExaDiS `MobilityLaw`, `Topology`, `CrossSlip`, or `Collision` implementation is connected to ExaDiS internals.
- No stock ExaDiS local-force audit has been performed by the branch code.
- No candidate junction, cross-slip, collision, or source-activation event is generated by the scaffold.
- No ExaDiS trajectory is altered by the Arrhenius hazard code.

## Critical physics correction

The original scaffold applied the EXP-floor shape to the complete free-energy scale:

```text
G_wrong(tau,T) = (H - k_B T S_kB) [ f + (1-f) exp(-a(tau/sigma_c)^n) ]
```

This is not the reduced Taylor DDD convention. The corrected convention applies the EXP-floor shape to the enthalpy branch and keeps entropy as an additive TST contribution:

```text
G(tau,T) = H [ f + (1-f) exp(-a(tau/sigma_c)^n) ] - k_B T S_kB
G_floor(T) = f H - k_B T S_kB
```

For the HT050/F020 campaign values, `H=0.50 eV`, `S=-9 kB`, `f=0.20`, and `T=1050 K`, the corrected floor is about `0.914 eV`. The old scaffold floor was about `0.263 eV`. At a `5e-10 s` timestep, this changes the high-drive per-step probability from order `0.02` to essentially unity, so the old analytical peak table and any old high-drive probability estimates must be regenerated.

## Native hook correction

The native hook header now:

- includes `<stdexcept>` because it throws `std::runtime_error`;
- computes EXP-floor barriers with entropy outside the floor shape;
- records `probability_dt = 1 - exp(-R dt)` in `ArrheniusMobilityLaw::audit()`, rather than storing the clipped `R dt` value.

## Remaining implementation work

The next implementation must proceed in the following order:

1. Freeze the stock ExaDiS FCC strain-hardening example as a reference.
2. Add instrumentation without changing physics.
3. Expose the actual nodal/segment force decomposition, resolved glide stresses, segment lengths, candidate topology reactions, before/after energetic changes, cross-slip candidate stresses, collision classifications, and plastic strain increments.
4. Verify that the instrumented stock ExaDiS run is numerically identical to the uninstrumented stock run.
5. Connect `ArrheniusMobilityLaw` first, reproducing the current signed Peierls forward-minus-reverse rate with `H_P`, `S_P`, and `v_P*` before replacing it with any EXP-floor Peierls fit.
6. Add forest/junction release hazards using event-conjugate force work.
7. Add paired junction formation/destruction kinetics with detailed-balance checks.
8. Add cross-slip hazards while retaining ExaDiS crystallographic candidate generation.
9. Treat only activated collision reactions stochastically. Geometric core overlap and remeshing remain deterministic numerical operations.

## Validation hierarchy

The validation sequence is:

```text
stock ExaDiS
instrumented stock ExaDiS with identical trajectory
Arrhenius Peierls-only
Arrhenius forest/junction kinetics
Arrhenius cross-slip
full mechanism-resolved model
```

Every stage must report stress-strain response, dislocation density, swept-area plastic strain, mechanism-resolved event counts, barrier distributions, `R dt`, selected events, and detailed-balance diagnostics where applicable.
